Usage

Default command runs scan + clients + timers:

renewhunt
renewhunt scan [paths...]
renewhunt scan -system          # also walk /etc/letsencrypt, cron, systemd
renewhunt live example.com api.example.com:8443
renewhunt -check-live example.com,api.example.com ./deploy
renewhunt clients
renewhunt timers
renewhunt -json
renewhunt scan -json ./deploy

Exit code 1 if any finding is BLOCKED; 0 otherwise; 2 on usage/errors.

Example against the fixture corpus:

renewhunt scan ./testdata
# BLOCKED on --days 80, RENEW_DAYS=83, renewBefore: 2160h
# RISKY on renewBefore: 720h, renew_before_expiry=60
#   fix: renewBeforePercentage: 33   (printed under each cert-manager hit)

Live probe

renewhunt live host[:port]… opens a TLS connection to each host you name (port 443 by default), reads the served leaf certificate, and reports lifetime, how much of it is used, days left, and issuer. A certificate still being served well past ⅔ of its lifetime means renewal is late, failing, or not reloaded by the server. Use -timeout to change the per-host timeout (default 10s). On the default command, -check-live a.example,b.example adds the same section to the combined report.
