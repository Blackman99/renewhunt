FAQ

Does renewhunt renew my certificates? No. Read-only audit of configs and schedulers.

How is this different from certfan? certfan checks whether every IP behind a hostname serves the same live certificate. renewhunt checks whether your renewal automation still makes sense when lifetimes shrink.

Will percentage-based cert-manager config be flagged? renewBeforePercentage scales with lifetime, so 15–50 is OK; only extreme values are flagged. Absolute renewBefore: 720h is RISKY and 2160h is BLOCKED, each with a suggested renewBeforePercentage: 33 replacement.

Do I need root? Only for -system paths you cannot read as a normal user. Scanning a repo copy of your configs works without root.

Live expiry probes? Yes, since v0.2: renewhunt live host… or -check-live on the default run. It is a single TLS connection per host to read dates and renewal timing; for checking that every IP behind a name serves the same cert, use certfan. Since v0.3, add -ari to also ask the issuing CA for its suggested renewal window.

What does -ari send to the CA? Two plain GETs: the CA's ACME directory and renewalInfo/<cert-id>, where the id is the issuer key id plus the serial of the certificate the host already serves publicly. No account, key, or order is involved.
