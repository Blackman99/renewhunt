RENEWHUNT — DOCS

Reference

Severity

  • BLOCKED — renew window past 64-day expiry (e.g. day 80/83 since issuance; renewBefore ≥ 64d; --days ≥ 64)
  • RISKY — day 60 since issuance (~4d margin); absolute renewBefore that squeezes 45-day profiles (e.g. 720h)
  • OK — absolute window within short-lifetime margins (e.g. ~14–30d before expiry)
  • INFO — day 30 or other context worth a human look

Live probe severity

  • BLOCKED — expired, under 7 days left, or no TLS handshake
  • RISKY — over 80% of lifetime used (past the ⅔ renewal point), not yet valid, or a chain that does not verify
  • OK — already on a 64-day or shorter certificate and renewing on time
  • INFO — 90-day or longer certificate that is fine today

ARI (with -ari)

  • BLOCKED — the CA moved the window early (before half the lifetime, usually a revocation) and that window has already passed
  • RISKY — still served after the CA's window closed, or an early window is open or coming up
  • INFO — inside the CA's normal window; an ARI-aware client renews now
  • No ARI support, an unknown CA, or a lookup error is reported in the ARI table and never changes severity

cert-manager

  • renewBefore accepts Go durations: 720h, 720h0m0s (kubectl export form), 43200m, "2160h"
  • Every RISKY/BLOCKED renewBefore carries a suggestion: renewBeforePercentage: 33 (cert-manager ≥ v1.16), or delete renewBefore to use the ⅓-lifetime default
  • renewBeforePercentage: 15–50 OK; under 15 RISKY (too little room to retry on 45-day); over 50 INFO (renews early); outside (0,100) BLOCKED

Patterns

  • renew-before-expiry / renew_before_expiry / RENEW_DAYS
  • --days N on certbot renew lines
  • renewBefore: <duration> and renewBeforePercentage: N (cert-manager)
  • Standalone 83, 80, 60, 30 on lines that mention renew/cert/acme/letsencrypt/…

Guidance: renew near ⅔ lifetime (≈ day 43 for 64-day). Prefer ARI or percentage-based windows.
